# protegey-landing

Public marketing site and partner API documentation for Protegey (Nuxt 4, SSR, deployed on Vercel).

```bash
npm install
npm run dev        # http://localhost:3000
npm run build      # production build (also runs the link checker)
```

## Partner API reference (`/api-docs`)

The narrative guides on `/api-docs` are hand-written (i18n keys under `api_docs.*`), but the
**complete reference** (every request field, response field, possible value, scenario, error,
webhook payload, lifecycle and sandbox trigger) is rendered from the catalog generated by the
backend. Do not hand-write field documentation: change the backend, regenerate, sync.

### Syncing the catalog

```bash
# 1. In protegey-backend: regenerate docs/partner-api-catalog.json
npm run catalog:export

# 2. Here: copy + split it into app/data/partner-api-catalog/
npm run sync:catalog
```

`sync:catalog` (`scripts/sync-catalog.mjs`) reads, in order:

1. `--from <path-or-url>` (`npm run sync:catalog -- --from ./catalog.json`) or the
   `PARTNER_API_CATALOG_SOURCE` env var;
2. `../protegey-backend/docs/partner-api-catalog.json` (sibling checkout);
3. the public endpoint `https://api.protegey.com/public/partner-api-catalog`.

It writes (and commits with the site, so the page never calls the API at runtime):

| File | Contents | Loaded |
| --- | --- | --- |
| `app/data/partner-api-catalog/index.json` | conventions, sandbox scenarios, webhook delivery + event list, module titles, endpoint summaries, lifecycles | bundled with the `/api-docs` page, server-rendered |
| `app/data/partner-api-catalog/modules/<module>.json` | one module's endpoints (params, errors), scenarios, response shapes | lazy chunk, fetched when the module section nears the viewport |
| `app/data/partner-api-catalog/webhook-events.json` | every webhook event's payload fields + examples | lazy chunk, fetched when the webhook list nears the viewport |

Internal `validators` metadata is stripped. Rendering lives in `app/components/catalog/` and
`app/composables/usePartnerApiCatalog.ts`.

### Deep links

The partner portal links to these anchors: `#catalog-kyc`, `#catalog-kyb`,
`#catalog-transactions`, `#catalog-cash-deposits`, `#catalog-alerts`, `#catalog-screening`,
`#catalog-shared-signals`, `#catalog-device-events`, `#catalog-behavioral-events`,
`#catalog-webhooks`, `#catalog-sandbox` (plus `#catalog-conventions`). Endpoints and webhook
events have their own anchors too (e.g. `#catalog-kyc-ep-kyc-create`,
`#catalog-webhook-kyc-status-changed`), which open the matching panel on load.
