# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm run dev       # Start development server
npm run build     # Build for production
npm run generate  # Static site generation
npm run preview   # Preview production build
```

There is no lint or test script configured. Nuxt's TypeScript build (`@nuxt/typescript-build`) provides type checking at build time.

## Environment Variables

Required in `.env`:
```
NOTION_API_KEY=          # Notion integration token
NOTION_DATABASE_ID=      # Notion database UUID for waitlist/contact entries
MAILTRAP_TOKEN=          # Mailtrap email delivery token
VERCEL_ANALYTICS_ENABLED=true
```

## Architecture

**Framework**: Nuxt 4 with Vue 3 (Composition API). Uses the Nuxt 4 `app/` directory layout — all frontend code lives under `app/`, not the project root.

**Key directories:**
- `app/pages/` — file-based routing. `products/[id].vue` is a dynamic product detail page (IDs: `signal`, `radar`, `api`, `console`, `compliance`, `panid`)
- `app/components/sections/` — all full-page section components (Hero, Footer, HeaderNav, FAQ, etc.)
- `app/components/products/` — product-specific sub-components
- `app/composables/` — `useTheme.ts` (dark/light mode via localStorage + `dark` class on `<html>`), `useSeoUtils.ts` (canonical URLs and alternate hreflang links)
- `app/layouts/default.vue` — wraps all pages; handles global `useHead` with Organization/WebSite schema.org, canonical links, and hreflang alternates
- `app/lib/utils.ts` — exports `cn()` (clsx + tailwind-merge)
- `server/api/` — three endpoints: `waitlist.post.ts`, `contact.post.ts`, `sitemap-urls.get.ts`

**i18n**: Three locales — `fr` (French, default, no URL prefix), `en` (`/en/...`), `ar` (`/ar/...`, RTL). Locale files at `i18n/locales/{en,fr,ar}.json`. Strategy is `prefix_except_default`. Arabic RTL support is handled by `dir="rtl"` set via `useLocaleHead` in the default layout and by `rtl:` Tailwind variants in components.

**Styling**: Tailwind CSS with `darkMode: 'class'`. Brand colors defined in `theme.config.js` (primary = lime/cyber green, secondary = cyber purple) and imported into `tailwind.config.js`. IBM Plex Sans Arabic is the global font. Custom `xs` breakpoint at 475px.

**SEO**: `@nuxtjs/seo` module handles sitemap, robots, OG images, and schema.org. Each page sets meta via `useSeoMeta()` and `useHead()`. The `useSeoUtils` composable generates canonical URLs and hreflang alternate links. The sitemap is dynamically generated by `/api/sitemap-urls`.

**Backend integrations**:
- **Notion**: Used as the database for waitlist sign-ups and contact form submissions. Both API routes check for duplicates before inserting.
- **Mailtrap**: Sends transactional confirmation emails in the user's selected locale (fr/ar/en). Email content is inlined HTML in the server route files.

**Animations**: GSAP (`gsap` package) for scroll/entry animations. Custom Tailwind keyframe animations defined in `tailwind.config.js` for background gradient blobs (`moveVertical`, `moveInCircle`, `moveHorizontal`).

**UI components**: `shadcn-nuxt` is installed for component primitives. Icons from `@hugeicons/vue` with `@hugeicons/core-free-icons`.

## Conventions

- All new pages must add `useSeoMeta()` and `useHead()` with geo meta tags to match the existing pattern in `app/pages/index.vue`.
- When adding i18n keys, add them to all three locale files (`en.json`, `fr.json`, `ar.json`).
- RTL layouts use Tailwind's `rtl:` variant (e.g., `rtl:text-right`, `rtl:flex-row-reverse`).
- The `cn()` utility from `app/lib/utils.ts` should be used for conditional class merging.
- All colors should reference the brand palette from `theme.config.js` via Tailwind tokens (`primary-400`, `secondary-500`, `neutral-950`, etc.) rather than raw hex values.
