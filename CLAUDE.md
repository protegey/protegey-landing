# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm run dev       # Start development server
npm run build     # Build for production
npm run generate  # Static site generation
npm run preview   # Preview production build
```

There is no lint or test script configured. Nuxt's TypeScript build (`@nuxt/typescript-build`) provides type checking at build time.

## Environment Variables

Required in `.env`:
```
NOTION_API_KEY=          # Notion integration token
NOTION_DATABASE_ID=      # Notion database UUID for waitlist/contact entries
MAILTRAP_TOKEN=          # Mailtrap email delivery token
VERCEL_ANALYTICS_ENABLED=true
```

## Architecture

**Framework**: Nuxt 4 with Vue 3 (Composition API). Uses the Nuxt 4 `app/` directory layout — all frontend code lives under `app/`, not the project root.

**Key directories:**
- `app/pages/` — file-based routing. `products/[id].vue` is a dynamic product detail page (IDs: `signal`, `radar`, `api`, `console`, `compliance`, `panid`)
- `app/components/sections/` — all full-page section components (Hero, Footer, HeaderNav, FAQ, etc.)
- `app/components/products/` — product-specific sub-components
- `app/composables/` — `useTheme.ts` (dark/light mode via cookie + `dark` class on `<html>`), `useSeoUtils.ts` (canonical URLs and alternate hreflang links)
- `app/layouts/default.vue` — wraps all pages; handles global `useHead` with Organization/WebSite schema.org, canonical links, and hreflang alternates
- `app/lib/utils.ts` — exports `cn()` (clsx + tailwind-merge)
- `server/api/` — three endpoints: `waitlist.post.ts`, `contact.post.ts`, `sitemap-urls.get.ts`
- `server/utils/rateLimit.ts` — in-memory sliding window rate limiter used by API routes

**i18n**: Three locales — `fr` (French, default, no URL prefix), `en` (`/en/...`), `ar` (`/ar/...`, RTL). Locale files at `i18n/locales/{en,fr,ar}.json`. Strategy is `prefix_except_default`. Arabic RTL support is handled by `dir="rtl"` set via `useLocaleHead` in the default layout and by `rtl:` Tailwind variants in components.

**Styling**: Tailwind CSS with `darkMode: 'class'`. Brand colors defined in `theme.config.js` and imported into `tailwind.config.js`. IBM Plex Sans / IBM Plex Sans Arabic is the primary font; Inter is the body/UI font. Custom `xs` breakpoint at 475px.

**Theming**: Dark/light mode is cookie-based (`theme` cookie) via `useTheme.ts`. The `useCookie` composable is used (no `default` option to avoid SWR header conflicts). A FOUC-prevention inline script in `nuxt.config.ts` reads the cookie synchronously before first paint. `error.vue` manages its own `useHead` htmlAttrs since it bypasses the default layout.

**SEO**: `@nuxtjs/seo` module handles sitemap, robots, OG images, and schema.org. Each page sets meta via `useSeoMeta()` and `useHead()`. The `useSeoUtils` composable generates canonical URLs and hreflang alternate links. The sitemap is dynamically generated by `/api/sitemap-urls`. Default locale (`fr`) has no URL prefix; `en` and `ar` have prefixes.

**Backend integrations**:
- **Notion**: Used as the database for waitlist sign-ups and contact form submissions. Both API routes check for duplicates before inserting.
- **Mailtrap**: Sends transactional confirmation emails in the user's selected locale (fr/ar/en). Email content is inlined HTML in the server route files. User input is sanitized via `escapeHtml()` before interpolation.

**Animations**: GSAP (`gsap` package) for scroll/entry animations. Custom Tailwind keyframe animations defined in `tailwind.config.js` for background gradient blobs (`moveVertical`, `moveInCircle`, `moveHorizontal`).

**UI components**: Icons from `@hugeicons/vue` with `@hugeicons/core-free-icons`.

**Security**: API routes use `server/utils/rateLimit.ts` (sliding window, in-memory). Security headers and CSP are set in `nuxt.config.ts` `routeRules['/**']`. HTML injection in emails is prevented via `escapeHtml()`.

**Deployment**: Vercel, `cdg1` (Paris) region. Configuration in `vercel.json`.

## Brand Style Guide

The official brand identity is defined in `theme.config.js`. All UI work must reference these tokens — never raw hex values.

### Color Palette

**Primary — Security Emerald**
Represents: Protection, Verification, Safety
```
primary-500: #0CB99E   ← main brand accent (buttons, highlights, CTAs)
primary-400: #2DD4B6   ← hover states, lighter accents
primary-300: #5EE8CC   ← subtle tints
```
Use `primary-500` for primary actions and key brand moments. Use `primary-400` for hover/focus states.

**Secondary — Tech Blue**
Represents: Innovation, Digital Connectivity, Platform Scalability
```
secondary-500: #1B59AE  ← main secondary color
secondary-400: #4A90D9  ← lighter interactive states
```
Use for secondary actions, information states, and paired with primary in gradients.

**Neutral — Deep Trust Blue family**
Represents: Trust, Security, Infrastructure
```
neutral-950: #060D1C   ← deepest dark background
neutral-900: #0B1741   ← Deep Trust Blue — dark bg, cards on dark
neutral-800: #0F1F4A   ← elevated surfaces in dark mode
neutral-700: #162558
neutral-600: #1E3169
neutral-500: #3A4E7A
neutral-400: #6B7EA3   ← muted text, placeholders
neutral-200: #C5CEDC   ← borders in light mode
neutral-100: #E2E7EF   ← subtle backgrounds in light mode

**Accent — Intelligence Cyan**
Represents: Technology, Intelligence, Data analysis
```

**Accent — Signal Orange**

### Dark/Light Mode Color Hierarchy

Light mode (no `.dark` class):
- Page background: `bg-neutral-50`
- Cards/surfaces: `bg-white`
- Inner cards: `bg-neutral-100/50`
- Borders: `border-neutral-200`
- Body text: `text-neutral-600`
- Headings: `text-neutral-900`

Dark mode (`.dark` class on `<html>`):
- Page background: `dark:bg-neutral-950`
- Cards/surfaces: `dark:bg-neutral-900`
- Inner cards: `dark:bg-neutral-800/30`
- Borders: `dark:border-neutral-800`
- Body text: `dark:text-neutral-400`
- Headings: `dark:text-white`

**Every color class must have a `dark:` counterpart.** Semi-transparent dark values like `dark:bg-neutral-900/50` on a `dark:bg-neutral-900` page create no visual separation — use a different tone instead.

### Typography

**Primary (headings, key messaging)**: IBM Plex Sans / IBM Plex Sans Arabic
- Tailwind token: `font-sans`, `font-display`
- Weights used: Light (300), Regular (400), Medium (500), SemiBold (600), Bold (700)

**Body/UI (long-form content, labels)**: Inter
- Tailwind token: `font-body`
- Weights used: Light (300), Regular (400), SemiBold (600), Bold (700), ExtraBold (800)

Arabic locale uses IBM Plex Sans Arabic (superset of IBM Plex Sans) — this is loaded via Google Fonts and is the correct choice for RTL support.

### Brand Personality & Voice
**Trustworthy · Confident · Intelligent · Protective · Forward-Thinking**

Aesthetic: Modern, Mature, Serious, Sophisticated, Geometric, Abstract.
Tone: Direct and authoritative — not playful or casual.

### Logo
- Composition: Shield + Eye + Scan Lines + Core Dot
- Shield = Protection, Eye = Vigilance, Scan Lines = Verification Technology, Core Dot = Digital Identity
- Exclusion zone: 4× logo height on all sides
- Minimum rendered size: 25% of original
- Source file: `app/assets/images/logo.png` (also mirrored to `public/images/logo.png` for static serving)
- Always use `<img src="/images/logo.png">` (static) in HeaderNav and Footer — not `<NuxtImg>` — to avoid SSR hydration mismatches

### Standard Gradients
```
Primary:  from-primary-400 to-secondary-400
Cyber:    from-primary-400 via-accent-cyan-500 to-secondary-400
Dark bg:  from-neutral-900 to-neutral-950
Glow:     from-primary-500/20 to-secondary-500/20
```

Hero headlines use a CSS gradient text technique:
```css
/* Light mode */
background: linear-gradient(135deg, #0B1741 20%, #0CB99E 60%, #1B59AE 100%);
/* Dark mode */
background: linear-gradient(135deg, #ffffff 20%, #0CB99E 60%, #1B59AE 100%);
```

## Conventions

- All new pages must add `useSeoMeta()` and `useHead()` with geo meta tags to match the existing pattern in `app/pages/index.vue`.
- When adding i18n keys, add them to all three locale files (`en.json`, `fr.json`, `ar.json`).
- RTL layouts use Tailwind's `rtl:` variant (e.g., `rtl:text-right`, `rtl:flex-row-reverse`). Directional arrow icons use `rtl:rotate-180`.
- The `cn()` utility from `app/lib/utils.ts` should be used for conditional class merging.
- All colors must reference brand palette tokens (`primary-400`, `secondary-500`, `neutral-950`, `accent-cyan-500`, etc.) — never raw hex values.
- New pages that use `InfoPage.vue` as a wrapper inherit the sidebar nav and prose styles automatically. Page-level cards inside InfoPage should use `bg-white dark:bg-neutral-900` for proper contrast against the `bg-neutral-50 dark:bg-neutral-950` page background.
- API routes must call `rateLimit(event, { max, windowMs })` at the top before processing, and sanitize user input with `escapeHtml()` before any HTML template interpolation.
